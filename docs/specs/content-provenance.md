# Content provenance

## Problem

The wiki grows from chat. When a page is proposed, reviewed, or later disputed, there is no record of
*what exact text* a write would commit, nor *which chat it came from and who said it*. Reviewers approve
blind, and a later reader cannot trace a claim back to its origin. As more of the wiki is generated by
agents, that missing lineage is the difference between a knowledge base you can audit and one you have to
take on faith.

## Approach

Attach a content-addressable hash to the two points that matter, and carry the chat link through to the
wiki proposal.

1. **Every chat turn is fingerprinted.** `ChatMessage` gains a `provenance` column, stamped on insert with
   `sha256(conversation_id : role : content)`. The hash is deterministic and content-addressable: identical
   text in the same conversation and role produces the same hash, so two writes of the same claim are
   detectably the same, and any later edit of the stored text no longer matches its own fingerprint.

2. **Every wiki proposal carries a fingerprint and a source link.** `WikiReview` gains
   `provenance_hash` (a `sha256` of the exact content the write would commit), plus
   `source_conversation_id` and `source_message_id` (nullable) that point back to the chat the content came
   from. The reviewer sees the fingerprint and a link to the originating chat before approving.

### Why hash the content, not the identity

The stamp answers "is this the same text, and did it come from where it claims?" It does **not** encode the
user id or message id into the hash. "From whom" is answered by the *link* (`source_conversation_id` ->
conversation -> user, and the review's existing `proposed_by`), which stays correct even when a message is
later edited, and is queryable. Baking identity into the hash would make it neither content-addressable nor
verifiable against the stored text. `message_provenance()` is a pure function so a reader can recompute a
message's fingerprint and confirm the row has not been tampered with.

## Data model

- `ChatMessage.provenance` `String(64)`, `default=""`, stamped by a `before_insert` mapper event
  (`_stamp_message_provenance`) so every creation site is covered without touching call sites. The event
  only stamps when the field is empty, so an explicit value (e.g. a re-import preserving the original hash)
  is never overwritten.
- `WikiReview.source_conversation_id` `Integer` FK -> `conversations.id`, nullable.
- `WikiReview.source_message_id` `Integer` FK -> `chat_messages.id`, nullable.
- `WikiReview.provenance_hash` `String(64)`, `default=""`.

New columns only; `migrate.ensure_columns` adds them to existing databases on startup, `create_tables`
covers fresh ones. No backfill: pre-existing messages and reviews keep an empty fingerprint, which the UI
simply omits.

## Wiring

`propose_wiki_write()` accepts `source_conversation_id`, `source_message_id`, and `provenance_hash`. When no
hash is passed it computes `sha256(content)` itself, so any caller that omits it still gets a fingerprint;
the source ids default to `None` for callers that have no chat origin (upload, connector import, research).
`memory_to_wiki` passes the memory's originating conversation (`MemoryItem.source_id` when
`source == "chat"`). `snippet_to_wiki` parses the snippet's `source_ref` (`"conv:42/msg:7"` for a chat
snippet) via `snippets.parse_chat_ref` and passes both the conversation and the exact message id, so a
snippet promoted to the wiki links all the way back to the turn it was clipped from. The review template
renders the fingerprint and, when a source conversation is known, a link to it.

## Follow-ups (not in P0)

- Surface a message's own fingerprint in the chat transcript UI.
- Recompute-and-verify affordance in the wiki page view ("this claim came from session #N, unchanged").

## Done after P0

- `snippet_to_wiki` now links back to the exact turn: the snippet already stores `source_ref`
  (`"conv:N/msg:M"` for chat snippets), so `parse_chat_ref` recovers the conversation and message ids and
  passes them through. Every wiki-write path with a chat origin (memory, snippet) now carries lineage.
