Lambda Labs launch config - Lambda serves on an always-on GPU VM

Advanced settings

On-prem and your own cloud VPC are always-on, green (fully your perimeter). A neocloud (Modal / RunPod) is per-use, amber - your account and your model, but inference transits a third party's shared GPUs, with a cold start on the first request after idle.

A provider-agnostic VRAM target: Anthill maps it to the concrete GPU your provider runs the model on - on RunPod the serverless GPU pool it provisions, on a cloud VPC a GPU instance of that size - so the list is the same whichever provider you pick. Fit is at full precision (what vLLM serves by default): ~2 GB per billion params, so a 70B needs about 140 GB and will not fit one of these GPUs. To run a big curated model (32B, 70B) on a single GPU, turn on Serve 4-bit (AWQ) below - it is roughly a quarter of the size, so a 70B fits a 48 GB GPU. The labels show the full-precision size; the 4-bit toggle raises what fits.

0 (default) scales fully to zero when idle - lowest cost, but the first request after idle is a cold start. A higher number keeps that many workers ready to bound cold starts, at ongoing cost even while unused.

Models are sized to your GPU size (VRAM): greyed ones need a bigger GPU (pick a larger one above to unlock them). The largest need Serve 4-bit (AWQ) - turn it on and a curated 32B or 70B fits a single normal GPU. A few are too big even at 4-bit and need multi-GPU serving.

Open Qwen models need no token. For a gated model, accept its license on Hugging Face and paste a read token here; Anthill passes it to the GPU so it can pull the weights (encrypted at rest).

Anthill provisions a GPU in your own AWS account only for a run, then releases it. Set up AWS once (below), paste the credentials here, and Test connection.

What to set up in AWS first ▾
  1. AWS account + billing for the company (one dedicated account is cleanest).
  2. Request a GPU quota increase - do this first, it can take hours-days to approve. Service Quotas → EC2 → "Running On-Demand G and VT instances" → request ≥ 4 vCPUs. New accounts start at 0, so nothing GPU will launch until this is granted.
  3. Pick a region with GPU availability (e.g. us-east-1, us-west-2).
  4. Create a least-privilege IAM user with programmatic access; save its access key ID + secret.
  5. Note a Deep Learning AMI for your region (optional; blank uses Anthill's validated default).
  6. Set an AWS Budget alert as a backstop (Anthill also enforces a max-runtime cap below).
Anthill only launches an allow-listed GPU type, tags it, caps its runtime, and always terminates it - with a boot-time reaper for any orphans.
